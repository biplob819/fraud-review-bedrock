# W0.1 acceptance criteria

One block per capability. Each criterion is checked by a named test.

**HAR-01 — uv project and package skeleton**
- `uv sync` succeeds; `fraud --version` prints `fraud 0.0.1`, also as `python -m fraudreview.cli`.
- `pyproject.toml` names the distribution `fraud-review-bedrock`, requires Python ≥3.12, declares the MIT licence and the `fraud` console script. `LICENSE` is MIT. Pre-commit runs ruff and the secret scan. `.gitattributes` forces LF.

**HAR-02 — CI**
- `ci.yml` runs on push to main and on pull requests; runs ruff, pyright, pytest, secret scan, graph eligibility, the honesty check and a wheel build; matrix covers Python 3.12 on Linux and macOS.
- Every workflow sets top-level permissions and reads no repository secrets; CI is `contents: read`.

**HAR-03 — graph eligibility**
- Fails on a cycle, an unknown dependency, an unparseable `depends_on`, a catalog row naming an unknown node, and a node building or starting ahead of a non-green dependency. Passes on the live graph. `--self-test` passes.

**HAR-04 — node start**
- Refuses when the node is unknown, has no catalog rows, a dependency is not green, the spec folder or any of `spec.md`, `criteria.md`, `tasks.md` is missing, or `criteria.md` misses a capability. On success writes `specs/<node>/.base`; `--mark-building` flips the node's rows; check-only writes nothing. `--self-test` passes.

**HAR-05 — node converge**
- Runs all 12 gates in the documented order (gate 8 = honesty) and reports every one even after a failure; exits 1 if any gate fails; writes a log under `.harness/<node>/`.
- `--self-test` shows every gate failing on bad input with the planted defect named in the output (the proof case, the broken `pyproject.toml`, the failing smoke command, the untested source file, the missing changelog entry), fails when `uv` is missing, and golden and honesty SKIP (not PASS) when there is nothing to check.
- Proofs resolve only to tests that exist in a `test_*.py` file and that the normal suite run (same collection as CI) records as passed through the harness's outcome plugin: module and class marks, `importorskip`, `__test__ = False`, uncollectable classes, files the suite ignores, xfail and XPASS (strict or not) and printed fake result lines all fail (D-29); gates 6, 7 (both legs) and 9 count outcomes the same way, so printed text never decides a gate, and a missing uv when gate 7's minimum-Python leg is needed is a FAIL (the documented `FRAUD_SKIP_MIN_PYTHON=1` switch skips that leg on purpose); the harness rejects outcomes not written by its own plugin file; a git error while listing files for the secret scan is a FAIL; a local file cannot shadow the plugin (tests that deliberately tamper with the plugin's records are out of scope); a run where every test skipped is SKIP for golden and FAIL for safety, never PASS; a tool error such as missing git, or a failing `git ls-files`, is a FAIL.

**HAR-06 — records**
- `graph.md` parses to 22 nodes (23 since OWNER D-36 added E2.4) with no cycle and no duplicate dependency; `catalog.tsv` parses to 108 rows (119 since D-36), each naming a graph node; every node has rows; the catalog round-trips byte for byte.
- `decisions.md` holds D-1 to D-29 and matches Tech Spec §1 cell for cell; `lessons.md` and `changelog.md` exist; `status.py` prints the graph table and a per-node table, deterministically.
- Public docs (PRD, Tech Spec, README, graph) carry no dates or time slots in any common form; no tracked file carries private content (generic patterns in the test, private terms in the git-ignored `.public-guard.local`); local notes are git-ignored.

**HAR-07 — secret scan**
- Detects every format in the `FAKES` and `MORE` tables of `tests/harness/test_secret_scan.py`: Anthropic, OpenAI, AWS (access keys; secrets and session tokens in env, JSON, YAML with `_` or `-`, Python repr, Terraform or STS text), Bedrock API keys (long-term, short-term, bearer env), Kaggle keys (JSON or env), GitHub, Slack (tokens, app tokens, webhook URLs) and PyPI tokens and private keys, including when `_`, `-`, `=`, a quote or other punctuation precedes the token (a letter or digit directly before it is read as part of a longer word); honours the `secret-scan: allow` marker; the live repo is clean.

**HAR-08 — honesty check**
- Purpose: catch a published number whose simulated-data label was forgotten or lost. It is not a defence against a deliberately misleading author.
- Flags every form in `honesty_check.SELF_TEST_CASES` (percentages, money with the unit before or after, per-thousand rates) on a source line with no visible label, naming file, line and metric. The file is parsed as CommonMark (0.31.2 comment rules: a comment ends at the first `-->`). Metrics are found in prose, tables, code and visible HTML text, with HTML entities decoded and Unicode format characters removed. A label is the word "simulated" in a prose text node on the metric's source line: not in code, inline HTML elements, autolinks, images, URLs of any scheme, link targets or footnote ids. A negator from the case table earlier in the same sentence on that line, in any visible text, voids every label after it in that sentence (conservative). A sentence ends at `.`, `!` or `?` followed by whitespace and a capital letter (initialisms such as `U.S.`, `e.g.`, `i.e.` in any case, and the abbreviations listed in `ABBREV_RE`, excepted), or at `; ` or `: `. Plain counts, versions and a metric's name without an adjacent number pass.
- In a paragraph where the parser hides a line break (inside a code span, link title or image alt), no label counts, and the reported line is the parser's count (approximate for that paragraph). HTML blocks are read with the standard-library HTML parser: comments (including `<!-->`), script, style and template content are not visible.
- A missing `docs/published.txt` or a listed path outside the repo fails; a listed file that is missing fails; `--self-test` passes; the live repo passes.
- A per-thousand rate counts when its number sits at most one word before it (with the same separators allowed), or after it with an optional noun of up to three words and any of `| , ( : = *` or dashes between (so a table row `| Cost per 1,000 alerts | 13.10 |` is caught). Tables (GFM, with or without outer pipes, and HTML `<table>`) are read from the whole document rendered to HTML, the way a browser builds them: a table spread over several Markdown blocks (Markdown inside a cell, blank lines between rows) stays one table, and a `<td>`/`<th>` with no open row starts one. A number cell is a metric when another cell in its row, its column header, or the table's corner cell names a unit (`%`, `‰`, `$ € £ ₹ ¥ ¢`, the codes USD, EUR, GBP, INR, JPY, the words percent, percentage, pct, dollar(s), cent(s), also inside snake_case names such as `recall_pct`, or a per-thousand rate). A header row is a row inside `<thead>` (unless it holds numbers under headers already read, as when `</thead>` is omitted), or, before any data row, a row of two or more cells whose filled cells are all `<th>`; once data rows have started, every row outside `<thead>` is data; consecutive header rows merge, and each header row after the first is itself judged against the headers read so far; a one-cell row is a title or section label: before any header or data row it lends its unit to the whole table, as a `<caption>` anywhere in the table does (each table is judged when it ends); a section row's unit after the headers is not carried to later rows (known limit); a table left open at the end of the file still counts; camelCase units, with the unit at the end or the start (`recallPct`, `costUSD`, `pctChange`, `usdCost`), count like snake_case. Labels never come from HTML blocks, so an all-HTML table with metric cells is labelled with a Markdown paragraph inside the cell. A line of pipe-separated text that is not a table is read the same way, without headers. Paths, filenames and other `name.ext` tokens, like URLs, never count as a label.
- Known limits, documented in the script: negation spanning source lines or worded outside the case table; a number and its unit split across two source lines; money or rates written wholly in words beyond the listed forms; a per-thousand rate whose number is more than one word away; GitHub-only syntax (footnote definitions, bare-email autolinks) is read as plain CommonMark. Table limits: a number cell is a cell holding only a number (optionally with `~ ≈ + -`), so `97.5 ± 0.3`, `97.5*` or `1.2k` cells are not judged by the table rule; `colspan` and `rowspan` are not followed when matching cells to columns; a number is attributed to the source line of its cell.
