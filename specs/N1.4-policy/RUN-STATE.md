## Open should-fix (carried forward)
- Always-true predicates (`amount >= 0`, `x or not x`) load; consider flagging tautologies at review.
- A `no_clear` that holds only because a value is missing reports `no_clear:<id>`; a distinct reason would read better in the audit log.
- `&` and `<` are refused in prose by design ("Fraud & disputes" must be written "Fraud and disputes"); revisit only if authors find it limiting.
- The eval/exec source test catches direct calls by name only (`getattr(builtins, 'eval')` would pass it); the code does neither.
- Clause-number look-alikes without a `P` (`Clause 9.9 forbids clearing`) and a letter after an exact id (`P7.1a`) load; wording-level.
- Ordered-list renumbering can change visible numbers in prose (`5.` then `9.` renders 5, 6); predicates are shown verbatim, so prose only.
- `_WITHDRAWN` has no trailing word boundary, so `voided`, `drafting`, `ignores` also match (fail-closed false positives for authors).
- A clause's kind can contradict its title or prose (`kind: clear` titled "Never auto-clear ..."); the yaml shows the real kind. Optional check: a title starting "Never auto-clear" requires `kind: no_clear`.
- Tags and anchors inside the fields list (`[!!str amount]`, `[&x amount]`) load; refusing `&`, `*` and tags anywhere in yaml lines would be simpler to state.
- `HEADING_RE` (n >= 1, at most three digits) is narrower than `schemas.CLAUSE_RE`; align when A2.2 validates cited ids.
