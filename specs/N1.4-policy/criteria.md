# N1.4 acceptance criteria

**POL-01 — policy v1**
- `policy.md` loads; it has at least one clause of each kind; every clause has prose; the clause ids the PRD examples use (P3.1, P4.2) exist with the meaning the PRD gives them, checked by evaluating them on alerts either side of the threshold.

**POL-02 — clause loader**
- Refuses, naming the clause: a clause without exactly one ```yaml block or with any other code block, a clause with no prose, YAML that does not parse or uses a tag the loader cannot build (including a duplicate key), keys other than id/kind/fields/when, an id that does not match its heading, a clause title that names a clause id, a duplicate id, an unknown kind, empty, non-list or repeated fields, a field not on the allow-list, an empty predicate, escapes or `#` comments in its yaml, a yaml block that is not exactly four plain `key: value` lines (trailing blank lines ignored) (id, kind, fields, when; a value may not start with an anchor, alias, tag, quote or block marker) of at most 100 characters with single spaces and no tabs (so the line shows in full on a desktop-width code view; narrow screens may scroll), and a clause title or prose that, as a reader takes it in (line breaks as spaces, `*` and `_` read both as emphasis and as literal marks, every run of other characters as one space), uses a listed withdrawal word or phrase (the distinctive entries are also matched with every non-letter removed, so hyphens or letter-spacing cannot split them) (withdrawn, repealed, superseded, void, rescinded, expired, not in force, no longer, do not use and the others in `policy._WITHDRAWN`). The same check runs over all text outside code blocks (naming the file), in every reading above. This list is defence in depth over natural language; other wording is left to review.
- Refuses, naming the file and line, anything outside the Markdown subset. Outside code blocks a line is blank (spaces and tabs only), a single `# Title` before the clauses, a `## P<n>.<m> Title` clause heading (ASCII digits, n from 1 and each part at most three digits, no leading zero; extra spaces and a closing `#` run are read as CommonMark renders them), or prose; it has no leading whitespace, is not a block quote, link definition, underline heading, rule or table delimiter row, is not a list item that starts another list, heading, quote, code block or rule, uses only ASCII letters, digits, spaces and `. , ; : ' " ? ! ( ) / % * _ # + -`, and has a space or line end after every `:` (so no `:name:` emoji shortcode). Together these leave out everything a renderer can turn into hidden, struck or replaced text (`<`, `&`, `|`, `\`, `~`, `[`, `]`, backticks, `$`, emoji shortcodes, non-ASCII); URLs with a scheme cannot be written (a `www.` name still renders as a link with the same visible text). Anywhere outside code blocks (the title, clause titles after their id, and prose, including across line breaks), every `P` or `p` that does not follow a letter and is followed by up to six non-alphanumeric characters and a digit (in every reading: the text as markdown-it renders it, and the raw text with `*` and `_` removed, read as spaces, and kept; each run of whitespace, line breaks included, read as one space) must be an existing clause id written exactly as `P<n>.<m>`. A code block must be closed and inside a clause. Also refused: a file that is not UTF-8, has an invisible, control or default-ignorable character (a leading byte-order mark is dropped, as renderers do), has no clause headings or no clear clause, or where the line scan and the CommonMark parse (markdown-it, nesting limit raised) disagree on clause headings or code blocks.
- Line endings follow CommonMark: CRLF and bare CR load like LF. Together these mean a clause the rendered file shows (on GitHub or in any CommonMark renderer) is a clause the loader reads, and the reverse.
- Clause prose and titles need a letter or digit in their rendered text. Beyond these rules, what prose says in plain words is left to review: the router enforces only the predicates. The loaded clauses cannot be altered (the mapping is read-only and a clause stores only immutable values).

**POL-03 — predicate parser**
- Accepts one-line predicates with single spaces: comparisons (including chained), and/or/not, field names and non-negative plain decimal number (at most 6 decimal places), known-category (exact spelling, one quoted string) or bool constants, in plain ASCII. Refuses calls, attributes, subscripts, arithmetic, lambdas, conditionals, comprehensions, a name the clause does not declare or a declared field it does not read, None, bytes or non-finite constants, comparisons across types, ordering on a category or bool, a comparison that reads no field, a `#` comment, a predicate over 300 characters (which also bounds nesting; any parser limit is a `PolicyError`, not a crash), and any condition that is not a true/false test (a bare number or constant). Predicates are never executed: there is no call to `eval`, `exec` or the `compile` builtin (checked on the source); `ast.parse` only builds a tree, which is walked.
- Evaluation reads a validated `AlertCase`; a missing or non-finite value fails safe by kind, and an `or` cannot route around it.

**POL-04 — version and prompt text**
- `version` changes when any byte of the file changes and is stable otherwise; `prompt_text()` keeps every heading and prose line and no YAML.

**POL-05 — clause validator and clearing rule**
- `unknown_clauses` returns exactly the cited ids not in the policy.
- `clearing_allowed(cited, case)` allows a clear only when a cited clear clause holds and no no_clear clause in the policy holds; otherwise it returns reasons naming each failing clause (`unknown_clause:`, `no_clear_clause_cited`, `predicate_false:`, `missing_value:` when a cited clear clause lacks a value, `no_clear:`).
