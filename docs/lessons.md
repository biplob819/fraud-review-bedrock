# Lessons

Numbered L-n. Each lesson names the failure, the rule it produced, and where that rule is enforced.
L-1 to L-17 are carried over from EvalKit ([EvalKit lessons](https://github.com/biplob819/evalkit/blob/main/docs/lessons.md), original id in brackets); where the enforcing code was ported, the rule holds here too, otherwise it is a rule for the node that builds that code.

| L-1 | [EvalKit L-1] A gate that has never failed is a gate nobody has checked | Every gate ships a `--self-test` that feeds it bad input and expects FAIL | `node_converge.py --self-test`, `tests/harness/` |
| L-2 | [EvalKit L-2] W0.1 verifier: the proofs gate accepted a test name found only in a comment, a string, a prefix or a skipped test | Proofs resolve through `ast` to a real `def test_*` in a `test_*.py` file, and the suite run must record it as passed; `logical` can never be n/a | `node_converge.proof_problems`, `node_converge.run_proofs` |
| L-3 | [EvalKit L-3] W0.1 verifier: a failed `git diff` against a bad `.base` was ignored, so gate 11 passed | A tool error inside a gate is a FAIL, never "no changes" | `node_converge.changed_files` |
| L-4 | [EvalKit L-4] W0.1 verifier: gate self-tests passed even when ruff, pyright or pytest were not installed | A self-test must require the planted defect's identity (rule code, file, test name) in the output, not just a non-zero exit | `node_converge.self_test` |

| L-13 | [EvalKit L-17] N1.2 verifier: fakes built flatter than the real SDK hid a wrong error-type path, and an expired batch discarded billed results | Fakes for SDK objects are built from the SDK models where possible; a terminal-but-failed batch still reads its output files | `test_anthropic_errored_item_keeps_the_real_sdk_error_type`, `test_expired_openai_batch_keeps_finished_results` |
